API error codes
This document deﬁnes the standardized error
codes for all public-facing endpoints maintained
by the api-platform-team. These codes provide
granular feedback for integration debugging,
ensuring that client implementations can
programmatically handle failure states. When
returning these errors, the response body must
include the string-based code and a descriptive
message.

Implementation guidelines
All FastAPI routes must use the standard
exception handler provided by the api-platform-
team library. Do not manually construct error
responses using raw dictionaries, as this
bypasses the global logging and telemetry
hooks. When encountering an ACME-4290,
clients are expected to respect the Retry-After
header. For ACME-5030 errors, implement
exponential backoﬀ to avoid hammering the
processor gateway during recovery cycles. If a
new error condition arises, consult with the api-
platform-team before introducing custom codes
to maintain consistency across the ecosystem.
