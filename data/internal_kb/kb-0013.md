# On-call escalation policy { #on-call-escalation-policy }

## Overview { #overview }

This document outlines the deprecated escalation procedures for the sre-team. While this policy has been superseded by updated workflows, it remains in the internal documentation archive for historical reference regarding incident response timing. All engineering staff should refer to the current operations handbook for active on-call protocols.

## Escalation mechanics { #escalation-mechanics }

In the event of a production incident, the monitoring system triggers an automated alert to the primary on-call engineer. To ensure timely resolution of critical service disruptions, the following escalation rule applies: if the primary on-call engineer does not acknowledge a page within 15 minutes, the secondary is paged. 

### Response requirements { #response-requirements }

The 15-minute window is measured from the initial timestamp of the alert delivery. Engineers are expected to acknowledge the page via the incident management platform to stop the escalation chain. Failure to acknowledge within this threshold triggers an immediate notification to the secondary responder to ensure that service level objectives are maintained. This automated handoff prevents silent failures in our alerting pipeline and ensures that the sre-team maintains adequate coverage during high-severity incidents. 

## Status { #status }

This policy is officially deprecated. Please do not apply these specific timing constants to new service configurations. Refer to the centralized configuration repository for the current, standardized escalation timeouts and team rotations.
