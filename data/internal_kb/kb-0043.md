# Code review guidelines { #code-review-guidelines }

This document outlines the mandatory review standards for the platform-team. All engineers are expected to adhere to these protocols to maintain system stability and financial integrity across our FastAPI services.

## Review workflow { #review-workflow }

Every pull request requires at least one approval from a senior engineer before merging. Reviewers are responsible for verifying that the code follows our established design patterns, utilizes appropriate dependency injection, and includes sufficient test coverage. We prioritize asynchronous reviews to minimize blocking, but critical patches may be elevated to the platform-team Slack channel for immediate attention.

## Financial safety requirements { #financial-safety-requirements }

Strict compliance is required for any logic involving transactional operations. Any changes that touch money movement need two approvals. These approvals must come from different engineers who are familiar with the payment gateway integration and ledger reconciliation logic. Do not bypass this requirement under any circumstances, as it serves as our primary defense against regression in accounting accuracy.

## Documentation and feedback { #documentation-and-feedback }

When providing feedback, prioritize actionable comments over subjective style preferences. If a reviewer suggests a significant architectural change, they must provide a concrete example or reference the relevant internal technical specification. All PRs must be linked to a Jira ticket, and the final state of the code must match the requirements defined therein. If a PR remains stale for more than 48 hours, the author should ping the assigned reviewers or escalate to the platform-team lead to resolve potential bottlenecks.
