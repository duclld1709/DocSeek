# Sandbox environment limits { #sandbox-environment-limits }

## Overview { #overview }

The api-platform-team maintains the sandbox environment to facilitate integration testing for external developers. This environment mirrors the production architecture of our FastAPI-based payment services but operates with isolated data stores. Developers should utilize this space for validating API contracts and webhook handling before attempting production implementation.

## Data retention policy { #data-retention-policy }

To ensure infrastructure performance and maintain security hygiene, the sandbox environment enforces strict data lifecycle management. All entities, including transaction logs, customer profiles, and settlement objects, are subject to automated purging. Sandbox data is deleted every 30 days. 

We do not provide recovery services for data removed during these cleanup cycles. It is the responsibility of the integrating engineering team to maintain their own state or test scripts if they require persistent data beyond this 30-day window. If your testing workflow requires long-term data persistence, please reach out to the api-platform-team via our internal ticketing system to discuss potential exceptions or dedicated testing instances.

## Usage guidelines { #usage-guidelines }

Do not use real customer data or production credentials within the sandbox. While the environment is logically separated, our security posture dictates that only synthetic, non-sensitive data should be used for testing purposes. Rate limits in the sandbox are set lower than production to prevent resource exhaustion. If you encounter 429 Too Many Requests errors during load testing, verify that your implementation follows the exponential backoff strategies documented in our developer portal. Ensure that all API calls are authenticated using the sandbox-specific keys provided in your account dashboard.
