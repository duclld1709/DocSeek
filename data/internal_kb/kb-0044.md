# Service-to-service authentication with dependencies { #service-to-service-auth-dependencies }

## Overview { #overview }

All internal service-to-service communication within the Acme Payments infrastructure must be authenticated via service tokens. The `api-platform-team` manages the authentication layer to ensure consistent identity propagation across our FastAPI microservices. This document outlines the mandatory implementation pattern for verifying these tokens.

## Implementation details { #implementation-details }

To enforce authentication, developers must utilize the shared dependency `require_service_token`. This utility is designed to be injected into route handlers using FastAPI's `Depends` or `Security` mechanism. By centralizing this logic, we ensure that every internal endpoint validates the request origin consistently.

When a service receives a request, the `require_service_token` dependency inspects the authorization header. If the service token is missing from the request or if the provided token fails cryptographic verification, the dependency raises an `HTTPException` with a status code of 401. This approach prevents unauthorized access to internal endpoints and ensures that the downstream service has a verified identity of the caller.

## Usage example { #usage-example }

To secure an endpoint, import the dependency and include it in the path operation function signature. The following pattern is the standard for all internal APIs:

```python
from fastapi import APIRouter, Depends, Security
from acme_auth import require_service_token

router = APIRouter()

@router.get("/internal/data")
def get_internal_data(token: dict = Security(require_service_token)):
    return {"status": "authorized", "service_id": token.get("sub")}
```

By leveraging `Security` over `Depends`, we explicitly signal to the OpenAPI documentation generator that this endpoint requires authenticated access. This metadata is critical for our automated security auditing tools. Any attempt to bypass this dependency or failure to handle the 401 response correctly will result in a deployment block during the CI/CD pipeline review process. For questions regarding token rotation or claim validation, please reach out to the `api-platform-team` via the internal engineering slack channel.
