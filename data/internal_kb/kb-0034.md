# Payout batch failures { #payout-batch-failures }

## Overview { #overview }

The automated payout batch process executes daily at 02:00 UTC. This system is managed by the payments-team and handles the disbursement of funds to merchants. Failures typically occur due to upstream connectivity issues with banking partners, database lock contention, or malformed transaction payloads in the staging queue.

## Incident response { #incident-response }

When a batch failure alert triggers, engineers must first investigate the logs in the centralized logging dashboard to identify the specific exception. Common failure modes include timeout errors during API handshakes or database deadlocks during ledger updates. Engineers should verify the integrity of the pending ledger entries before attempting any corrective actions. 

## Recovery procedure { #recovery-procedure }

Once the root cause has been addressed, the batch must be reconciled to ensure no duplicate disbursements occur. After validation, the failed batch can be re-run manually using the `payq-retry` command. This command triggers the workflow engine to re-process the pending items in the batch. Do not execute this command until the initial failure cause is fully resolved, as repeated attempts against a locked or misconfigured resource may lead to inconsistent state in the payout ledger. Monitor the metrics dashboard for 15 minutes post-retry to confirm that the batch successfully transitions to a completed state.
