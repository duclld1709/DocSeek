# Getting started with the Acme Payments API { #getting-started-with-the-acme-payments-api }

## Overview and prerequisites { #overview-and-prerequisites }

The Acme Payments API provides a standardized interface for processing transactions. This documentation is maintained by the api-platform-team. All integrations must begin in our isolated testing environment to ensure adherence to our security standards and API contract requirements. Before initiating any API calls, ensure your local development environment is configured to handle HTTPS requests and that you have generated the necessary API keys through your developer dashboard.

## Sandbox environment and testing { #sandbox-environment-and-testing }

All initial development and integration testing must occur against the sandbox base URL: https://sandbox.api.acme-payments.example. This environment mirrors production behavior but operates exclusively on non-financial data. You are responsible for verifying your error handling logic using our provided test data. 

Specifically, developers must validate their failure handling mechanisms using the test card number 4000 0000 0000 0002. This specific identifier is hardcoded to always trigger a decline response from our processor. Integrating this test case into your automated test suite is mandatory to verify that your application correctly handles and surfaces payment rejections to the end user. If you encounter unexpected behavior or 5xx errors while using these test cards, please contact the api-platform-team via our internal communication channels for debugging assistance.
