# Rotating JWT signing keys { #rotating-jwt-signing-keys }

## Overview { #overview }

This document outlines the deprecated procedure for managing JSON Web Token (JWT) signing keys within our authentication infrastructure. The security-team is responsible for the oversight and execution of these key lifecycle events. While this policy has been superseded by newer automated secret management protocols, it serves as a reference for historical system behavior and legacy integration requirements.

## Rotation cadence and overlap { #rotation-cadence-and-overlap }

To mitigate the risks associated with long-lived credentials, JWT signing keys were previously rotated on a strict 90-day cycle. This frequency ensured that exposure windows remained limited while providing sufficient time for key distribution across distributed services. 

To prevent authentication failures during the propagation of new keys, we implemented a grace period. The previous signing key remained valid for 7 days after the rotation date. This overlap period allowed services to continue validating tokens signed by the outgoing key while transitioning to the new primary key. Engineers were required to ensure that all FastAPI services were configured to support multiple active public keys during this transition window. Any service failing to handle the dual-key state during the 7-day overlap would experience rejection of legitimate tokens, leading to potential downtime for end-user sessions.

## Implementation notes { #implementation-notes }

When this policy was active, the security-team utilized a centralized key store to distribute public keys to consuming services. Verification logic was implemented using standard Python JWT libraries, ensuring that the `kid` (Key ID) header parameter was used to fetch the appropriate public key from the local cache. If a token was received with a `kid` corresponding to the retired key, the system would accept it until the end of the 7-day grace period. After this window, the key was purged from the store, and any subsequent attempts to use the retired key resulted in a 401 Unauthorized response.
