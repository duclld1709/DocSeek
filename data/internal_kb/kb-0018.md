# PCI DSS scope and cardholder data zones { #pci-dss-scope-and-cardholder-data-zones }

## Scope definition { #scope-definition }

This document defines the strict boundaries for the cardholder data zone (CDZ) to maintain PCI DSS compliance. The CDZ constitutes the most restricted segment of our production infrastructure. To minimize the attack surface and simplify audit requirements, we enforce a strict isolation policy. Only the `vault-service` and the tokenizer are authorized to run inside the cardholder data zone. All other microservices, including those handling transaction metadata or auxiliary payment processing logic, must remain outside this zone. Any proposal to introduce new services into the CDZ requires a formal architecture review and security sign-off by the security-team.

## Access controls and audit requirements { #access-controls-and-audit-requirements }

Access to the cardholder data zone is restricted to authorized personnel only. We enforce multi-factor authentication requirements that mandate the use of a hardware key for every connection attempt. Access is granted on a least-privilege basis and is strictly logged for forensic auditing. 

To ensure continued compliance and reduce the risk of privilege creep, all access permissions to the CDZ are reviewed every 90 days. During these quarterly reviews, the security-team must verify that every user still requires access to perform their operational duties. Users who have moved teams or no longer work on the `vault-service` or tokenizer will have their access revoked immediately. These logs and the results of the 90-day review cycles are retained for audit purposes to demonstrate ongoing adherence to PCI DSS standards. Any deviation from these access protocols constitutes a critical security incident.
