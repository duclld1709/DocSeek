# Postmortem of the May 2026 webhook storm { #postmortem-of-the-may-2026-webhook-storm }

## Summary { #summary }

On May 14, 2026, the api-platform-team experienced a critical incident resulting in a webhook storm. A regression in our retry logic caused the system to dispatch 1.2 million duplicate webhooks to merchant endpoints over a period of 40 minutes. This surge saturated our egress gateways and caused latency spikes across the payments infrastructure, impacting downstream service availability.

## Timeline { #timeline }

- 14:00 UTC: Incident triggered by a deployment containing an updated retry policy configuration.
- 14:05 UTC: Monitoring alerts indicated a 500% increase in outbound webhook traffic.
- 14:15 UTC: The api-platform-team identified the failure in the idempotency key validation layer.
- 14:40 UTC: The system was successfully mitigated by rolling back the deployment and clearing the retry queue.

## Root cause { #root-cause }

The issue originated from a bug in the retry mechanism where the exponential backoff scheduler failed to verify the existence of previous delivery attempts. This caused the worker nodes to ignore existing status records in our Redis cache, resulting in the redundant dispatch of payloads that had already been successfully acknowledged by the receiver. The lack of an upper bound on concurrent retries per merchant allowed this process to spiral until the egress capacity was exhausted.

## Action items { #action-items }

- Implement a strict per-merchant delivery cap to prevent a single account from saturating outgoing traffic bandwidth. This has been merged and deployed as of May 16.
- Enhance the idempotency validation middleware to perform a synchronous check against the primary database before queuing any retry event.
- Introduce automated circuit breakers that trigger when outbound request volume deviates significantly from the 7-day rolling average for specific merchant IDs.
- Conduct a comprehensive audit of the retry configuration service to ensure that future policy updates cannot bypass existing safety constraints.
