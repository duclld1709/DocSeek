# Authenticating API clients { #authenticating-api-clients }

All external API clients interacting with Acme Payments services must authenticate using the OAuth2 client credentials flow. This standard ensures that machine-to-machine communication remains secure by decoupling client identity from user sessions. The `api-platform-team` maintains this implementation to enforce strict authorization boundaries across all microservices.

## Implementation details { #implementation-details }

When developing endpoints in FastAPI, developers should leverage the `OAuth2PasswordBearer` dependency to handle token extraction from the Authorization header. While this utility is named for password flows, it is the standard mechanism for parsing Bearer tokens in the FastAPI ecosystem. Once extracted, the identity provider validates the token against the registered client credentials. 

Applications must verify that the token scope matches the requested resource. If a token is malformed, expired, or lacks the necessary permissions, the service will return a 401 Unauthorized response. Developers are responsible for implementing appropriate error handling to gracefully manage these authentication failures in client-side integrations.

## Token lifecycle { #token-lifecycle }

Security policies mandate that all access tokens expire after 3600 seconds. Clients are expected to monitor token validity and perform a refresh or re-authentication request before the expiration threshold is reached. 

Hard-coding token lifetimes is prohibited. Instead, services must rely on the metadata provided by the identity server. By enforcing a 3600-second window, we minimize the blast radius of a potential credential leak. The `api-platform-team` recommends that clients implement an exponential backoff strategy when requesting new tokens to prevent service degradation during periods of high concurrency. All production services must log authentication attempts to facilitate audit trails and monitor for anomalous traffic patterns.
