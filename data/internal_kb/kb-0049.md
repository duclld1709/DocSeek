# Feature flag rollout { #feature-flag-rollout }

## Overview { #overview }

This runbook defines the standard operating procedure for deploying feature flags within the Acme Payments infrastructure. The platform-team mandates these steps to ensure system stability and to mitigate risk when introducing new logic into the FastAPI-based services. All engineers must follow this phased approach to prevent cascading failures.

## Rollout phases { #rollout-phases }

Feature flags are rolled out incrementally to ensure that system telemetry remains within acceptable bounds. The mandatory rollout percentages are 1%, 10%, 50%, and finally 100% of merchants. This progression must be strictly observed. 

At each percentage interval, the engineer responsible for the deployment must wait at least 30 minutes before proceeding to the next tier. During this 30-minute window, the engineering team is required to monitor error rates, latency metrics, and database contention. If any anomalies or performance regressions are detected, the flag must be disabled immediately, and the rollout halted until a root cause analysis is completed.

## Monitoring and verification { #monitoring-and-verification }

During the rollout, verify the health of the service using the standard dashboard. Pay specific attention to the 5xx error rates for the specific endpoints affected by the flag. If the error rate exceeds the baseline established prior to the activation, revert the flag to the previous state. Do not attempt to bypass these intervals or skip stages, even for minor changes. Documentation of the rollout progress should be updated in the internal tracking system upon completion of each phase. Once 100% rollout is achieved and the system remains stable for an additional 30 minutes, the feature flag can be considered successfully deployed.
