# Use FastAPI for new HTTP services { #use-fastapi-for-new-http-services }

## Context { #context }

The platform-team has standardized the internal service architecture to ensure consistency, performance, and maintainability across our distributed systems. Following an evaluation of our existing ecosystem, we have determined that all new HTTP services at Acme are built with FastAPI. This decision leverages FastAPI's asynchronous capabilities and native support for Pydantic models to enforce strict request validation and type safety.

## Implementation Strategy { #implementation-strategy }

Engineers should organize service logic using `APIRouter` to maintain modularity as endpoints scale. Furthermore, we rely on the `Depends` injection system to manage shared resources, such as database sessions or authentication providers. This pattern decouples business logic from infrastructure concerns, making unit tests easier to implement and maintain. By utilizing these primitives, we reduce the boilerplate code typically associated with request handling and dependency management in Python.

## Legacy Migration Policy { #legacy-migration-policy }

We acknowledge that a significant portion of our legacy infrastructure currently runs on Flask. To prioritize development efficiency, we are not pursuing a wholesale refactor of these services. Instead, Flask services are migrated only when they need a major change. This approach allows us to allocate engineering resources toward building new features while ensuring that critical legacy services are modernized only when the scope of work warrants the migration effort. This policy maintains project velocity while slowly phasing out older patterns in favor of a unified FastAPI-based stack.
