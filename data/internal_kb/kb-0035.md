# Rotating database credentials { #rotating-database-credentials }

## Overview { #overview }

This runbook outlines the operational requirements for managing database credentials within our FastAPI infrastructure. Maintaining strict credential hygiene is critical for compliance and security for our FastAPI services. All database access is governed by the `creds-rotator` job, which is configured to rotate credentials every 60 days automatically. This ensures that long-lived secrets are minimized without requiring a manual deployment.

## Credential rotation policy { #policy-details }

The `creds-rotator` job operates as a scheduled cron task within our orchestration layer. It retrieves new ephemeral credentials from the secret manager and updates the environment variables of the target containers. During this process, the application maintains a connection pool transition period to prevent connection drops. Engineers should not manually modify these credentials in the database or the secret manager, as this will lead to desynchronization and service outages.

## Troubleshooting and verification { #troubleshooting }

If a service reports authentication failures following a rotation event, verify the `creds-rotator` logs in the centralized logging dashboard. Check if the secret manager successfully updated the underlying vault path. If the service is still holding stale credentials, attempt to restart the affected pods to force a re-read of the environment configuration before forcing a full cluster restart. Ensure that the database user permissions have not been revoked or altered by an external process during the rotation window.

## Escalation { #escalation }

If rotation failures persist beyond the initial investigation, contact the platform-team via the internal engineering communication channel. Provide the specific service identifier and the timestamp of the failed rotation event. If the failure involves a potential security compromise or unauthorized access attempts, initiate a manual audit of the affected service immediately. Document all findings in the incident management system to support our ongoing compliance reporting.
