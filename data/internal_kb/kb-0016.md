# Python Service Template { #python-service-template }

## Overview { #overview }

All new Python services must be initialized using the current template maintained by the platform-team. This standardization ensures consistency across our microservices architecture, simplifies observability integration, and enforces security best practices from the start of the project lifecycle.

## Runtime Specifications { #runtime-specifications }

Standardized services must target Python 3.12. This version is the minimum requirement for all new repositories to leverage improved type hinting, performance gains in the interpreter, and enhanced error messages. CI/CD pipelines will reject deployments that do not conform to this specific interpreter version.

## Injection Strategy { #injection-strategy }

To maintain decoupling and promote testability, our FastAPI services utilize the built-in dependency injection system. All dependencies must be declared using `Annotated` in function signatures. This approach allows us to separate infrastructure concerns, such as database sessions or authentication headers, from the request handling logic. For example, a database session is injected using `db: Annotated[Session, Depends(get_db)]`.

## Implementation Details { #implementation-details }

Developers must use the `Depends` utility to resolve dependencies at runtime. When a request hits an endpoint, the framework evaluates these annotations and injects the required objects. This pattern keeps business logic clean and ensures that shared resources are correctly managed and closed by the application container. Any deviation from this pattern requires an explicit review from the platform-team to ensure that local implementations do not bypass established lifecycle management protocols.
