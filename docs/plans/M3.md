# M3 plan: dense retrieval with Qdrant

1. `configs/models.yaml`: embedding candidates bge-small-en-v1.5 (384d) and
   snowflake-arctic-embed-s (384d), each with model-card prefixes (`prefixes:` block; fastembed
   adds none itself). nomic (137M) dropped: ~1 h per embed on this CPU; e5-small-v2 is not in fastembed.
2. `dense/embedders.py`: `FastEmbedEmbedder(query_prefix, passage_prefix)`, `CachedEmbedder`
   (`.npy` + keys per model under `data/index/emb/`, key = sha256(model, prefix, text)).
3. `dense/qdrant_store.py`: named vector `dense`, payload indexes (acl, doc_type, source,
   status, modality keyword; updated_at datetime), UUID5 point ids, idempotent upsert
   (collection named by model + corpus hash; skip when complete), `MetadataFilter` → Qdrant
   filter, ACL `MatchAny(groups)` always added.
4. `dense/retriever.py`: `DenseRetriever`; register `dense` in the runner (location:
   `:memory:` | URL | path).
5. Tests (`QdrantClient(":memory:")` + `HashEmbedder`): Leakage = 0 via `probe_leaks` incl.
   permission queries, filters, idempotent upsert, embed cache.
6. `scripts/m3_embed_bench.py`: cold embed time, dim, cache size per model → experiments/.
7. Experiments: dense_bge_small, dense_nomic on dev → pick best → test once; BM25F vs dense by
   qtype with p-values (`results_table.py`), win/loss examples via `eval compare`.
8. Docs: results/M3, milestones/M3, progress; tag `m3-dense`.
