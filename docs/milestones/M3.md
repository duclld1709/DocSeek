# M3 — Semantic Search with Qdrant (đề bài)

> Buổi 04. Tag tham chiếu: `m3-dense`. File này là **đề bài**, không chứa lời giải.
> So sánh với tag tham chiếu bằng **cùng golden_v1, cùng split, cùng metric**.

## Mục tiêu

Dense retrieval trên Qdrant: hiểu embedding, prefix theo model card, payload filter, và biết
**khi nào dense thắng/thua BM25** bằng số có kiểm định thống kê.

## Việc cần làm

1. **Embedder** (`dense/embedders.py`): batch, L2-normalize, **cache `.npy`** theo hash của
   (model, phía query/passage, prefix, text). Đọc model card: model nào cần prefix cho query,
   cho passage? Thư viện bạn dùng có tự thêm prefix không? (kiểm tra trong source).
2. **Qdrant store** (`dense/qdrant_store.py`):
   - named vector `dense`; payload index cho `acl`, `doc_type`, `source`, `status`,
     `modality`, `updated_at`;
   - upsert **idempotent** theo `chunk_id` (gợi ý: UUID5); chạy lại không nhân đôi điểm.
3. **Retriever dense**: ACL luôn nằm trong filter của Qdrant, suy ra từ principal; hỗ trợ
   `MetadataFilter`. Principal lạ phải bị từ chối (fail closed).
4. So sánh **2 model** (một là `bge-small-en-v1.5`): chất lượng, dim, thời gian embed toàn
   corpus, kích thước vector.
5. Bảng **BM25 vs dense theo `qtype` kèm p-value**; liệt kê query dense thắng/thua kèm ví dụ.
6. Viết 1 câu: ACL pre-filter vs post-filter + over-fetch cho BM25, tradeoff là gì?

## Acceptance criteria

- [ ] Test với `QdrantClient(":memory:")` + `HashEmbedder` (không cần mạng, không cần docker).
- [ ] Leakage@10 = 0 cho mọi principal, có test riêng với các query `permission`.
- [ ] Upsert idempotent có test.
- [ ] Bảng BM25 vs dense theo `qtype` kèm p-value; split `test` chạy một lần cho cấu hình cuối.

## Câu hỏi để tự kiểm tra

- Với vector đã normalize, cosine và dot product khác nhau ở đâu (nếu có)?
- HNSW là xấp xỉ: làm sao biết recall của ANN so với exact search trên corpus của bạn?
- Vì sao dense có thể thua BM25 ở query `symbol` như `BackgroundTasks`?

**Giả thuyết:** dense thắng ở `conceptual`/paraphrase, thua ở `symbol`.
