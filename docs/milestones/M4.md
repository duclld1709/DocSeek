# M4 — Hybrid Retrieval + Reranking (đề bài)

> Buổi 05. Tag tham chiếu: `m4-hybrid`. File này là **đề bài**, không chứa lời giải.
> Báo cáo trên **golden_v1 (chính)** và golden_v2 (pooling), cùng split, cùng metric.

## Mục tiêu

Kết hợp BM25 và dense, rerank bằng cross-encoder, và đo **chất lượng tăng thêm so với
latency** để chọn cấu hình mặc định có lý do.

## Việc cần làm

1. `hybrid/normalization.py`: min-max, z-score. Quyết định: tất cả điểm bằng nhau thì ra gì?
2. `hybrid/fusion.py`:
   - **RRF tự cài**, k ∈ {30, 60};
   - **weighted sum** sau normalize, α ∈ {0.3, 0.5, 0.7}. Chunk chỉ có ở một danh sách thì
     lấy điểm gì ở danh sách kia? Ghi lại lựa chọn.
3. **Qdrant Query API**: `prefetch` (sparse + dense) rồi fusion RRF, chạy 1 lần để so với bản
   tự cài. Gợi ý: muốn BM25 chạy *trong* Qdrant thì vector sparse cần chứa gì, và idf lấy từ đâu?
4. **Cross-encoder** `bge-reranker-base` rerank top-N, N ∈ {20, 50} (thêm 100 nếu đủ nhanh).
   Đo p50/p95 trên CPU; vẽ **nDCG@10 theo latency**.
5. **Golden v2**: pool top-10 từ 3 retriever, LLM judge chấm các cặp chưa có nhãn
   (`reviewed: false`), không bao giờ ghi đè nhãn v1. Ước lượng chi phí **trước** khi chạy.
6. Reranker có đẩy hard negative xuống dưới positive không? Đo tỉ lệ.

## Acceptance criteria

- [ ] Unit test RRF bằng ví dụ tính tay + biên: list rỗng, trùng id, tie.
- [ ] Leakage = 0 cho mọi retriever mới (hybrid, Qdrant hybrid, rerank).
- [ ] Hybrid tốt nhất ≥ max(BM25, dense) về nDCG@10 trên test, hoặc giải thích bằng số.
- [ ] Biểu đồ quality–latency và khuyến nghị cấu hình mặc định.
- [ ] `golden_v2.jsonl` + ghi chú review; chi phí judge lấy từ trace.

## Câu hỏi để tự kiểm tra

- Vì sao RRF không cần normalize điểm, còn weighted sum thì cần?
- Khi nào rerank top-50 tệ hơn top-20?
- Metric trên v2 cao hơn v1: retriever tốt hơn, hay chỉ là nhãn đầy đủ hơn?
