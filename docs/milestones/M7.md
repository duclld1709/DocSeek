# M7 — Document Parsing (OCR) + Multimodal (đề bài)

> Buổi 08. Tag tham chiếu: `m7-multimodal`. File này là **đề bài**, không chứa lời giải.
> Đo parsing bằng số (CER/WER so với ground truth), không bằng cảm giác.

## Mục tiêu

Đưa PDF scan, bảng và ảnh trong docs vào cùng một trải nghiệm retrieval, có ACL và trích dẫn
được "trang X của file Y".

## Việc cần làm

1. `docseek data make-scans`: ~20 trang docs (có bảng, code) + ~10 doc KB (có bảng SLA, Error
   codes) → HTML → PDF → raster 150 DPI → nhiễu scan (xoay, blur, noise, contrast), một phần
   2 cột → PDF **không có text layer**. Ground truth = chính text đã in lên trang.
2. `ingest/pdf_parser.py`: trang có text layer thì đọc thẳng, không thì OCR.
3. `ingest/ocr.py`: so sánh Tesseract với RapidOCR (hoặc Docling) và một vision LLM: CER, WER,
   giây/trang, $/trang, trang 2 cột (reading order), độ chính xác ô bảng.
4. Chunk từ scan: `modality="scan"`, provenance `page`, ACL của tài liệu gốc. Corpus biến thể
   trong đó đáp án **chỉ** còn ở bản scan; golden cũ phải trỏ đúng sang trang tương ứng.
5. Ảnh (≤ 150, bỏ icon < 5 KB): alt text, OCR text, caption (vision LLM, cache), CLIP vào named
   vector `image`. Ba cách retrieval: CLIP; caption + OCR; fusion. Đo trên query `image`.
6. Router: `scan` → hybrid trên chunk scan; `image` → image retriever.

## Acceptance criteria

- [ ] Bảng OCR: engine × CER × WER × giây/trang × $/trang × độ chính xác bảng.
- [ ] Bảng image retrieval 3 phương án, có nhận xét chi phí.
- [ ] Query `scan` và `image` có trong eval tổng; Leakage vẫn = 0.

## Câu hỏi để tự kiểm tra

- Vì sao ground truth phải lấy từ đúng những gì in lên trang, không phải từ markdown gốc?
- Engine trả về chuỗi rỗng thì CER trung bình nói gì, và nên báo cáo thêm số nào?
- Một section không có trong `sections.jsonl` (chỉ tồn tại như chunk) thì Leakage@k tính thế
  nào cho đúng mà vẫn fail closed?
- CLIP "đọc" được chữ trong screenshot đến mức nào?
