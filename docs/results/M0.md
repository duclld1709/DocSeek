## Findings that matter for M1 (parser)

- **Lines starting with `#` but no `{ #anchor }`: 1,022 in total.** Of these, 958 are in
  excluded pages (mostly `release-notes.md` version headings). In the 150 indexable pages:
  - **19 sit inside fenced code** (shell and Python comments). These are not headings, so
    the parser has to track code fences.
  - **45 are real headings without an anchor**, spread over 27 pages and mostly in
    `reference/` (for example ``# Background Tasks - `BackgroundTasks` ``). Anchors need a
    slug fallback.
- **Include paths resolve from `docs/en/`** (the mkdocs project directory), not from the
  page's own folder: `../../docs_src/x.py` → `<repo>/docs_src/x.py`.
- **Variant preference.** Only `_py310` and `_an_py310` exist, so the spec's rule "prefer
  `_an_py310`" is enough. `ln[...]` selects line ranges and must be honoured when resolving.
- **Other syntax:** mkdocstrings directives (`::: fastapi.BackgroundTasks`), YAML front
  matter (`release-notes.md`), tabs (`//// tab | …`), `<div class="termy">`.
- **`resources/`** is a top-level directory that is not in the spec's `doc_type` list. It
  will map to `other` unless decided otherwise in M1.

## Engineering notes

- **Windows `localhost` penalty.** On Windows, `localhost` tried `::1` first, while compose
  binds IPv4 only, so each new connection cost about 2 s: Qdrant check 2.14 s vs 0.09 s, Neo4j check 2.07 s vs
  0.03 s with `127.0.0.1`. Defaults now use `127.0.0.1`, and `doctor` went from 7.6 s to 2.4 s.
  This matters for every latency number in later milestones.
- **Line endings.** `core.autocrlf=true` is set system-wide on this machine. Without
  forcing `autocrlf=false` in the clone, manifest hashes would differ between Windows and
  Linux.
- **Neo4j driver 6.4.1 works with server 5.26.32**, verified by an integration test.
- **Logging bug found and fixed.** A logger bound at import time froze structlog's
  defaults (console output, no level filtering). Covered by a regression test.
- **CI:** `astral-sh/setup-uv` publishes no floating `v10` tag; it is pinned to `v10.3.0`.
  GitHub warns that `ubuntu-latest` moves to Ubuntu 26 from 2026-10-19.
