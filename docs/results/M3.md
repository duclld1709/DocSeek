All numbers come from run directories under `experiments/` created on 2026-10-18 (named
below). Golden set `golden_v1` (dev 99 / test 149 queries). Qdrant v1.19.2 in docker, HNSW
defaults, cosine on L2-normalised vectors. **LLM cost of M3: $0.**

| snowflake/snowflake-arctic-embed-s | 384 | same | 104 s | 0.8 s | 9.0 ms | 2.19 MB |

- Embed times are wall clock on the dev laptop CPU. The machine was not idle during the
  bge-small run (unit tests ran alongside), so treat 988 s as an upper bound; a separate

- nomic-embed-text-v1.5 (137M, 768d) was the planned second model; it was dropped because a
  corpus embed would take about an hour here. e5-small-v2 is not available in fastembed.

## Analysis

- **Overall a tie** on test (0.641 vs 0.644, p = 0.93), but the two fail on different
  queries — the precondition for hybrid fusion (M4).
- **Hypothesis confirmed in direction.** Dense is better on `conceptual` (+0.12) and loses on
  `symbol` (−0.21, the only significant per-type difference, p = 0.014).
- **Dense wins (examples, test):** q0084 "verify my API endpoints without starting a real
  server" → `TestClient` reference (BM25: nothing relevant in top 10); q0107 "strip prefixes from operation
  identifiers before creating my SDK"; q0010 "which API edition they want" (KB versioning
  convention); q0162 "how to declare Annotated dependencies" (an internal-KB convention page).
- **Dense losses (examples, test):** q0108 "FastAPI Body examples parameter multiple JSON
  schema" (−1.0), q0125 "how to use Header in fastapi", q0122 "Response class usage xml",
  q0129 "get_settings() lru_cache optimization": short identifier-heavy queries where exact
  token match (`Header`, `lru_cache`) is the signal and dense similarity spreads to
  neighbouring sections.
- **Latency:** dense p50 13.8 ms (query embedding + Qdrant HTTP) vs 2.3 ms for in-process
  BM25F. On dev the first run measured p50 106 ms because the bge query embeddings were cold.
- **ACL in BM25 (one-sentence tradeoff):** BM25 uses a pre-filter mask, which costs an O(N)
  mask per principal but always returns k readable hits, whereas post-filtering with
  over-fetch is cheaper per query yet can return fewer than k hits when a principal can read
  only a small slice of the top results.
- Skipped by scope: cosine vs dot and with/without prefix experiments.
