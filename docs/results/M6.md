## When graph beats vector retrieval (and when it doesn't)

Examples from dev (`eval compare fresh_ctx_dev hybrid_graph_w…graph-0.2_min_entities-2_dev`):

- **Graph wins when the query names two specific things that co-occur in one section.**
  q0113 "FastAPI Response parameter status_code" (+0.37 nDCG): `shared_mentions` and
  `code_examples` on `Response` put `response-change-status-code.md#use-a-response-parameter`
  in the graph's top 3, a section whose prose is thin but whose code example uses `Response`.
  q0131 "FastAPI root_path usage" (+0.13): the concept "root path" localises all hits to
  `behind-a-proxy.md`.
- **Graph loses when the linked entities are generic.** `FastAPI` is mentioned by 733 of 1,345
  sections and links on almost every query; concepts such as "param", "default value" or
  "response model" (63 sections) fan out over `linked_pages`. q0100 "does FastAPI include default
  values in response_model…" (−0.50) and q0096 "can fastAPI handle multiple body params" (−0.37)
  get neighbouring-but-wrong sections pushed above the vector hit.
- **Why multihop does not improve here:** the golden multihop queries are paraphrased
  ("How should I structure my user data objects if I need to handle sensitive credentials
  securely?") and rarely name the API elements or concepts that connect their two sections, so
  entity linking finds nothing specific (dev: `credential`, `user`, `optional`), while the
  dense side already reaches 0.67–0.69 Recall@10. The graph's strength — exact relations
  between named entities — needs entity-rich questions ("which docs_src examples use
  `OAuth2PasswordBearer` with `Security`", "when did `Depends` change"), which the golden set
  barely contains. Those remain useful as **agent tools** (M8), not as a default retriever.
- Improvements not pursued in M6 (they would need another test run): drop APIElements by the
  same document-frequency rule as concepts (removes `FastAPI`), weight entities by specificity,
  and a larger model for concept extraction.

## Filesystem view

`docseek project` wrote 200 files (`data/projected/{fastapi-docs,internal-kb}/…`) plus
`_manifest.json`. Tools (`fs/tools.py`): `ls`, `find`, `grep` (literal or regex, ≤ 50 results,
pattern ≤ 200 chars), `cat` (line ranges or `section_id`, ≤ 200 lines / 8,000 chars). Files a
principal cannot read raise the same error as missing ones; `_index.md` is rendered from the
manifest per principal, so titles of restricted pages never appear. Not evaluated as a
retriever: it is the agent's navigation tool (M8).
